# 04-robotics — 纯 numpy 的四足步态控制器与接触约束仿真

参照 MIT Cheetah / `unitree_legged_sdk` 一类四足堆栈的设计，不依赖 MuJoCo、Drake
或任何物理引擎，全部 numpy 实现。核心是一个**运动学仿真器**而不是动力学仿真器：
机身怎么动，完全由「落地的脚不打滑」这一条约束解出来。

```bash
python -m quadruped.test_quadruped    # 24 项自校验测试
python demo_trot.py                   # 8 组机动指令对照表 + demo_trot.svg
```

## 目录

| 文件 | 内容 |
|------|------|
| `kinematics.py` | 3-DOF 腿（γ 侧摆 / α 髋 / β 膝）FK、闭式 IK、解析雅可比、可达性钳制 |
| `gait.py` | 步态相位、`foot_cycle` 摆动/支撑轨迹、`turn_cycle` 转向、`yaw_travel` 精确合成、Raibert 落足点 |
| `controller.py` | `TrotController`（步态 + Raibert 反馈 + 偏航前馈）、`KinematicSimulator`、2D Procrustes 位姿解算 |
| `stabilizer.py` | 凸包 / 支撑多边形 / 稳定裕度 / 切比雪夫中心 / ZMP / 摩擦锥力分配 |

## 已知边界（诚实记录）

- **运动学仿真，不是动力学仿真。** 忽略 roll/pitch、地面反作用力与足端滑移；接触被
  建模为「世界坐标位置冻结」。这足以严格检验步态逻辑（步幅守恒、速度跟踪、偏航率、
  支撑相连续性），但无法回答「会不会翻」「足端会不会打滑」。
- **`stabilizer.py` 的力分配是静态的，且摩擦锥是投影而非重解。** 用伪逆解接触力，
  再把越锥的切向分量就地限幅；限幅后竖直分量仍满足旋量，但**切向总量不再满足**——
  实测 50 N 前推时有 21.2 N 剪切被丢掉。它只用于回答「力矩可行吗」，不参与仿真闭环。
  真正要做可行域需要 QP 或分层分配。
- **爬行步态只验证了支撑多边形，没有真正实现机身横移。** 测试与 demo 量化了「名义
  质心裕度为 0、切比雪夫中心有 6.7 cm 余量」，横移控制本身未实现。
- **接触集在交错落地时可能只剩 1 个约束**，此时偏航在运动学上不可观测，代码会退回
  全部继承接触（见 DESIGN.md 第 5 节）。这是对退化情形的处理，不是完整解。
- **dt 与步态周期不整除时会引入 1 tick 的边界量化。** trot 周期 0.4 s 配 dt 2 ms 刚好
  整除；0.5 s 配 2 ms 不整除，此时相位会跨过边界而不是正好落在边界上。已处理，但这是
  采样事故而非设计意图。
